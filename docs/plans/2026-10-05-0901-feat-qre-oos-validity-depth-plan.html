Requirements

OOS validation methodology

  • R1 Lớp OOS-validity mới cung cấp đúng ba protocol: purged K-fold với embargo gap, walk-forward anchored, CSCV/PBO — tồn tại như module thuần trong package validation/.
  • R2 Property tests + known-value tests chứng minh bất biến chống leakage: không fold nào để nhãn vượt qua embargo, train window không bao giờ nhìn ra ngoài thời điểm dự đoán, CSCV/PBO tái tạo đúng giá trị tham chiếu đã công bố (Bailey–López de Prado).
  • R3 Đánh giá OOS đi qua đúng pipeline experiment hiện có (ExperimentRunner/BacktestEngine), không tạo pipeline backtest song song.

Study v2 — experiment

  • R4 Study v2 chạy trên ba DGP predeclare với seed cố định — null iid, injected-skill, overlapping-label — dùng chính strategy grid của generator hiện tại.
  • R5 Mỗi DGP so sánh baseline pipeline hiện tại (full-sample + DSR) với lớp honest (walk-forward + purged CV + CSCV/PBO) trên cùng dữ liệu.
  • R6 Metrics predeclare — selection inflation Δ(IS−OOS Sharpe) với bootstrap CI, PBO, false-selection rate dưới null DGP, DSR trước/sau — "kết luận có nghĩa" = Δ khác 0 ở 95% CI, hoặc PBO > 0.5 cho best-of-N selection, hoặc false-selection rate lệch khỏi nominal 5% ngoài CI.
  • R7 Replication trên fixture thật nhỏ (closes từ Polymarket/Kalshi) được fetch đúng một lần rồi commit vào repo; mọi lần chạy study sau đó hoàn toàn offline.
  • R8 Output là results/overfitting-study-v2.json (schema predeclared: config hash, dataset id, per-method metrics, conclusion) cùng document .md sinh hoàn toàn từ JSON — không số liệu tay.

Reproduction & CI gate

  • R9 make reproduce (hoặc entrypoint tương đương) tái tạo study byte-identical từ clone sạch, offline, sau khi dependency đã được pin.
  • R10 CI GitHub Actions mới gate: pytest + mypy strict + lint + regenerate-and-diff; đỏ ngay khi số công bố drift.
  • R11 Reproduction được chứng minh trên ≥2 môi trường (CI và một môi trường local khác phiên bản lock).
  • R12 Coverage gate (fail_under) bật trong CI, mypy strict=true giữ nguyên.

Success Criteria

Exit khi đủ cả năm:

  1. Reproduce byte-identical chứng minh trên ≥2 môi trường bằng một lệnh (AE1).
  2. Lớp validation đủ 3 protocol, property/known-value tests xanh; coverage gate + mypy strict + ruff 0 đều green trong CI.
  3. Một kết luận naive-vs-honest cụ thể, có CI, đọc từ results/overfitting-study-v2.json — không số tay.
  4. README evidence-rich + toàn bộ docs truth-up (R14, R15).
  5. 5 falsification conditions đã evaluate xong, không còn mục open.

Falsification Conditions

Predeclare (KD5) — nếu một điều kiện trigger, đúng hành động đó phải diễn ra, không nới ngưỡng:

FC1 — Determinism thất bại: byte-diff vẫn còn sau khi pin dependency và fix các lớp nondeterminism trong Phase 4 → kiến trúc reproduce bị loại; re-scope, không tuyên bố "tái tạo được".

FC2 — Honest ≠ naive: Δ CI chứa 0 và false-selection ≈ nominal trên mọi predeclared DGP → câu hỏi research yếu; ngừng thêm complexity, báo cáo null result trung thực.

FC3 — CSCV/PBO không khớp known-value reference (Bailey–López de Prado worked examples) → implementation CSCV bị loại hoặc thay bằng reference tái tạo được; claim thu hẹp lại.

FC4 — Fixture fetch thất bại (API chết / licensing chặn) → bỏ real replication; claim thu hẹp về synthetic-only, quyết định lại scope trước khi tiếp tục.

FC5 — Replication thật ngược chiều synthetic → generalizability claim bị điều kiện hoá (conditional); README phản ánh đúng ranh giới.
